# 当前版本 CSV 试验采集

双击 **Start_CSV_Capture.cmd** 打开采集窗口。复用本机 `learning/nn_fpga/.venv` 和 pyserial 3.5；采集工具本身只接收数据，使用的固件以当前注册表为准。

## 第一次试验

1. 烧录 `fpga/final_scan_v3_20261016/FINAL_TEAM_CURRENT.bit`，使用完整32路扫描版。
2. 使用USB串口，SW0置逻辑0；SW7置逻辑0，不扣背景。先固定光源、位置和增益。
3. **停止并退出占用串口的 LabVIEW 上位机**。本工具要独占串口，不能与上位机直接同时读取。
4. 打开本工具，点击“刷新串口”。选择实际COM号；以前是COM10，但端口号可能变化。多个端口时由你明确选择。
5. 标签先填写“室内灯”“遮光”或“强光试验”，批次例如 `20261016_01`。增益请记录实际设置；工具不会读取或更改板卡增益。
6. 点击“开始采集”。等待1秒并丢弃后续2个完整帧后，开始写CSV。先各录30秒，点击“停止采集”。
7. 点击“打开数据文件夹”，在Excel里查看文件。完整数据默认在本工具的 **datasets** 文件夹中。

每次开始新建一个 CSV，不覆盖已有文件。数据在每帧写入后flush；正常停止/关闭窗口会关闭文件。采集中请不要用Excel打开正在写入的文件；先停止再查看，避免文件占用影响写入。异常退出时已写入的行通常保留，但突然断电不保证最后一行落盘。

## 数据内容

每一行是一次完整32路扫描的平均结果：`CH00_code`～`CH31_code`为整数ADC码，保留所有零值及可疑通道，无排序、补值或平滑。按当前上位机显示比例可用 `code/4096` 换算显示电压；未经板卡链路校准，不代表已校准的探测器绝对电压。
其他列记录接收时间、试验标签、批次、增益备注、背景备注、预期固件SHA256、完整帧十六进制及帧序号。时间是电脑接收时间，`frame_index`是本次保存行数，均不是FPGA时间戳/设备帧号。
`suspect_channels=0;1`对应之前单通道CH09、CH07的疑似异常，只作标记，照常保留值。所有32路均保存，之后训练再明确31维特征选择。
固件SHA只核对本机封存文件，**无法从串口自动证明板卡当前烧录的就是v3**；请人工确认。增益和SW7也无法自动读取，只保存你填写的备注。
CSV使用UTF-8 BOM，支持中文标签；请保留原始CSV，避免用Excel另存时改变整数、时间和十六进制格式。

## 随时删除

在窗口的文件列表中选一个CSV，点击 **删除所选数据集**。确认后永久删除该文件；如果它正在采集，会先停止并关闭文件。再次开始会新建CSV。
也可以停止采集后直接在资源管理器删除 `datasets` 中不需要的CSV。工具只管理这个文件夹，不提供删除工程、BIT、训练环境等其他文件的功能。删除文件不会删除已发送到FPGA的程序。

## 协议与限制

串口固定115200、8数据位、偶校验、1停止位；只接收，不发送板卡指令。
每帧64字节：32个小端16位字，后接 `FF FF`，总计66字节。当前固件是12位双极性ADC负向取幅值，正向截零，所以有效整数码0～2048。
只保存长度、码值范围均合法的帧；异常片段计数并丢弃，不补零，随后用帧尾恢复对齐。启动时打开到一半的帧可能产生一次拒绝片段，属重新对齐的正常现象。若持续拒绝或超过5秒无有效帧，请检查COM号、是否烧录v3、SW0及接线。
**当前固件没有CRC、设备帧序号或时间戳，无法识别所有位错误、统计所有丢帧，或证明32路同时采样。**CSV中的 `validation=length_range_only_no_crc` 明确记录这一点。读取错误会停止并提示，保留已写文件。
